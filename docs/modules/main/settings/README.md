# Settings

The Settings section is always shown at the bottom of the sidebar. Its page, at `#/settings`, is the app's own page (`src/main/settings/SettingsPage.tsx`), not a markdown file. It is the one place where the user adjusts the app.

## What the page holds

- **Appearance**: the Theme control, with System, Light and Dark. Changing it applies the choice to the app, to the pages and to every running mod at once, visible or hidden, without reloading the page or any mod's frame. System follows the operating system's preference. (The Theme control used to sit in the header.)
- **Sidebar**: every section of the app, in the sidebar's order. Home, Settings and About say "Always shown". Each optional section, coming-soon ones included, has a switch labeled with its name, and a coming-soon section, Mosaics in the vanilla app, also says "Coming soon". A section whose mod the instantiation switched off is not listed (see the [section registry](../README.md#sections-of-switched-off-mods)).
- **Privacy**: the "Load media linked by tiles" switch, on by default. On, mods can show the images, audio and video their tiles link to, from any public site, without a permission (see [Media linked by tiles](../../lib/core/sandbox/README.md#media-linked-by-tiles)); the group says that the linked sites can see that the user viewed the tile. Off, mods show only media from where their files and tiles were loaded and from the hosts of their granted `show` permissions. A change applies to mods opened after it: running mods keep what they were started with, and no frame reloads. The store (`src/main/settings/tile_media_setting.ts`) gives the stage its start value (`readStartTileLinkedMedia`) and tells it of each change (`changeStageTileLinkedMedia`).
- **Mod permissions**: the decisions remembered in the site consent dialog (see the [stage dialogs](../README.md#stage-dialogs)), in one group per mod file and one per mosaic file, sorted together by title, then address. A mosaic's group starts its button with the label `Mosaic`, so the button reads, for example, `Mosaic Nobel books 1 allowed`, and shows the mosaic file's address under its header; a mod's group has no label. Everything else works the same for both, and applies to that mod or that mosaic only. The group's description states the cost, as the dialog does: each site a mod is allowed to use can see that the user used that mod, and sites allowed to exchange data or load code can also receive what the mod shows or keeps. With no decision, it says `No remembered decisions.`
  - **Each group** starts collapsed every time the page opens. Its header starts with the group checkbox (named `Allow all decisions of <title>`): checked when every decision of the mod is allowed, unchecked when every one is refused, and mixed otherwise. Checking it when unchecked or mixed allows every decision of the mod, and unchecking it refuses every one, without expanding the group. Then a button showing the mod's title, taken from its latest remembered decision, and its counts, such as `1 allowed, 2 refused`; clicking it expands or collapses the group (`aria-expanded`). Next to it, **Remove all** (named `Remove all decisions of <title>`) removes every decision of that mod at once, without expanding the group. The mod file's address is shown under the header.
  - **Each decision**, once its group is expanded, shows the line in the dialog's words (such as `show content from https://upload.wikimedia.org`), sorted by category and host, with its Allowed checkbox before it (named `Allow <title>: <line>`, checked when allowed), `Allowed` or `Refused` after it, and a Remove button (named `Remove <title>: <line>`).
  - **Sites always played from**, after the groups: each host the user chose to always play from in the player dialog (see the [stage dialogs](../README.md#stage-dialogs)), as `play media from <host>`, followed by `Every mod`, since the choice applies to every mod, and a Remove button (named `Remove: play media from <host>`). Removing it applies to the next player of that host, which asks again; a player already shown keeps playing. The list is left out when no host is remembered. The store (`src/main/settings/player_sites.ts`) is read by the player dialog when it opens, and written by its Play button and by Remove.
  - **Changes apply to mods started after them**, without asking. Checking or unchecking a decision, or a whole group, changes it between allowed and refused, so the next time that mod is opened its permissions are granted or denied as changed. Removing a decision, or all of a mod's, makes the dialog ask again. A group left without decisions disappears. Running mods keep their permissions, and no frame reloads. The store (`src/main/settings/site_decisions.ts`) gives the stage `readSiteDecisions` and `rememberSiteDecisions`. Site-permission choices are checkboxes, as in the dialog, while the page's other groups keep their switches. Settings changes decisions with `rememberSiteDecisions`, one decision or all of a mod's or a mosaic's in one call, and removes them with `removeSiteDecision` and `removeDeclaredSiteDecisions`, which takes the group's `DecisionDeclarer` (`subject` and `source`).
- **Version**: the app's version, labeled `OpenTesela`, and the app's mod API version, labeled `Mod API`. The app's version is the one in `package.json` when the app was built (`src/main/app_version.ts`, see the [release guide](../../../releasing.md)), and the mod API version is `MOD_API_VERSION` (see [the engine](../../lib/core/engine/README.md#mod-api-version)). Both are plain text, so the user can select them and copy them into a problem report.

## Stored keys

The app keeps the user's choices in `localStorage`, under keys that start with `opentesela.` but not with `opentesela.mod-storage:`, so no mod storage slot can read or write them:

| Key | Value |
|---|---|
| `opentesela.theme-choice` | `system`, `light` or `dark`. A missing or unknown value is System. |
| `opentesela.sidebar-sections` | The section switches, `{ "<section id>": false }` for a section switched off. A section with no stored switch is on, so a section an instantiation adds starts shown. A switch of a section the registry no longer has is dropped on the next start. |
| `opentesela.tile-linked-media` | "Load media linked by tiles": `true` or `false`, as JSON. A missing or other value is on. |
| `opentesela.site-decisions` | The remembered site decisions, a JSON array of `{ mod, title, category, host, allowed }` or `{ mosaic, title, category, host, allowed }` (`SiteDecision`, see the [permissions module](../../lib/core/permissions/README.md#decisions)): exactly one of `mod`, the mod file's address, or `mosaic`, the mosaic file's address, each an absolute `http:` or `https:` URL, so an entry with both or neither is dropped, and an older app drops a mosaic entry rather than misreading it; `title` the mod's or the mosaic's title when the user answered; `category` one of `show`, `connect`, `embed`, `code` and `open`; `host` as declared, non-empty; `allowed` a boolean. An entry that is not a valid decision is dropped, and of two entries for the same `mod` or `mosaic`, `category` and `host` the later one is kept. A mod entry and a mosaic entry for the same address and host are two decisions. The cleaned list is written on the next change. |
| `opentesela.player-sites` | The hosts the user always plays from, for every mod, a JSON array of host names as `URL.hostname` gives them, such as `["www.youtube-nocookie.com"]`. An entry that is not a host name is dropped, and a repeated host is kept once. The cleaned list is written on the next change. |
| `opentesela.sidebar` | The sidebar's layout on viewports at least 768px wide: `{ state, from, width }`, the state (`expanded`, `collapsed` or `hidden`), the state a hidden sidebar comes back to, and the expanded width. An invalid value gives an expanded sidebar of 240px. Nothing done on a narrow viewport is stored. |

When the storage cannot be read or written (a private window, a full or blocked storage), the choices still apply until the page is closed, and no error is shown.

## What hiding a section does, and does not do

Switching a section off only removes its item from the sidebar, at once and without reloading anything. Switching it on brings the item back at its place.

- Its links still work: `#/run?mod=mod_explorer` still runs the explorer while Mods is hidden, and `#/guides` still shows the Guides page while Guides is hidden. A link from a page or a mod still opens it.
- While a section is hidden, nothing it shows makes a sidebar item current. Once it is switched on again, its item is current when what it holds is shown: the stage keeps each entry's section whether or not its item is shown.
- It does not switch a mod off, close a sandbox or remove a page. Switching a default mod off is the instantiation's choice, in the default mod settings.
